## 1. Goal

Complete the offline-first loop on top of the G2 card renderer: persist before generation, save the file, invoke system sharing when available, classify failures, and recover cleanly after cancellation.

## 2. Completed

- Persist the current game draft and card ratio/theme to `xdrate.games.export-snapshot.v1` before PNG generation or sharing;
- Distinguish save success, user cancellation, and write failure while keeping the current draft intact;
- Keep browser/Toy on download-style file saving and reuse the desktop platform file adapter;
- Invoke Web Share with an image `File` when the host supports it; otherwise explain that the user can save PNG and share it from the album;
- Detect stale generated images before sharing; when content changed, show three choices: “Generate new image / Cancel / Share old image,” with Cancel in the middle;
- Preserve the draft and the previous generated image after sharing or saving failures;
- Keep the old image in memory for the current session only, avoiding large PNG payloads in localStorage. Snapshot metadata remains available for future recovery prompts.

## 3. Platform boundary

“Save PNG” is the stable generic-platform capability. Writing directly to a system album requires a native host Bridge, so the Toy/browser build does not claim album permissions it does not have. System sharing likewise depends on `navigator.share` and host support for image-file sharing.
