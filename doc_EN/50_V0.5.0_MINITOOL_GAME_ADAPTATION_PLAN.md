# V0.5.0 MiniTool Game Adaptation Plan

Status: adaptation plan; the game Toy has an independent entry, while the game MiniTool is not yet delivered

Date: 2026-09-27

## 1. Context and objective

The repository's current `minitool:build` still builds the music Xiaohongshu MiniTool. The game product already has its own page, game templates, eleven card ratios, and a Toy build, but it has no game MiniTool entry. Reusing the existing command would produce a music rating package and would not be a valid game deliverable.

This plan adds an independent offline game MiniTool so users can open the game rater in the Xiaohongshu container, apply a template, edit scores, generate a rating-card PNG, and save it to the system album with recoverable native capability errors.

## 2. Scope

### Required

- An independent game product shell and game fields;
- Four covered personal-rating templates plus the standard blank template to the left of Black Myth: Wukong;
- Simple, professional, and custom modes, axes, reasons, deductions, and an optional personal signature;
- Eleven image ratios with a shared immutable snapshot for preview and PNG export;
- Local draft and template restoration;
- MiniTool native album saving with capability probing and success, cancellation, rejection, unavailable, and failure states;
- Chrome 61 / Android 8.1 compatible classic-script output;
- Offline loading with relative package-local resources.

### Out of scope

- `postNote` publishing;
- Online game data, accounts, rankings, or cloud sync;
- `a[download]`, `window.open`, clipboard APIs, and external CDNs;
- Using the music MiniTool or Toy page as the game entry;
- A second game scoring algorithm. The shared `music-linear-100-v4` contract remains the scoring contract.

## 3. Technical design

### 3.1 Independent entry

Add `minitool-game/index.html` and a game MiniTool Vite configuration. The entry renders the game domain directly and does not switch between music and game through a query parameter. The output goes to `dist-minitool-game/` and the ZIP root contains `index.html`.

The game and music MiniTools use separate builds, version labels, storage keys, and package names so a release cannot accidentally upload the music page as the game package.

### 3.2 Container adapter

Add a game MiniTool platform adapter that provides runtime detection, `writeTempFile` plus `saveImageToPhotosAlbum`, normalized result classes, browser fallback, and duplicate-request protection. The adapter may call only the documented `window.xhs.miniTool.*` APIs.

### 3.3 Export consistency

The editor, preview, PNG exporter, and album saver consume the same immutable snapshot. A revision and ratio are recorded before rendering; if the draft changes afterwards, the user is asked to generate a new image. All eleven ratios, the nine-axis Black Myth template, long content, no-cover content, and the blank template use the same export planner.

## 5. Storage rules

- Use `xdrate.games.minitool.workspace.v1` and `xdrate.games.minitool.templates.v1`;
- Never read or overwrite music MiniTool data;
- Treat the blank template as an ordinary deletable template, while adding it once during migration when an older catalog lacks it;
- Keep cover references package-local or runtime-local; do not serialize cover binaries into templates;
- When storage is unavailable, keep the current session usable and show an unsaved-state notice.

## 6. Acceptance matrix

- First open selects Black Myth: Wukong and shows all nine axes;
- Applying the left-side blank template clears work fields and axes into custom mode;
- Simple, professional, and custom modes work, and applying a template never mutates the seed;
- Red Alert 2 official worldview is preset to 6 with level 2 weight;
- All eleven ratios generate matching previews and PNGs without overflow;
- Album success, cancellation, denial, missing Bridge, and exceptions are visible and retryable;
- ZIP, path, classic-script, Chrome 61, blocked-API, size, and offline audits pass;
- Safe area, keyboard, touch scrolling, and album permission flow are checked on a real device.

## 7. Deliverables and release order

Deliver `dist-minitool-game/`, a versioned ZIP under `artifacts/minitool/`, its manifest and SHA-256, bilingual adapter notes, Bridge result records, and device evidence. The release order is local tests, static audit, ZIP verification, manual preview, real-device album test, MiniTool preview upload, and explicit confirmation before review submission.

## 8. Exit criteria

The game MiniTool builds independently, keeps the default and blank template behavior, renders the nine-axis game score consistently across page, preview, and PNG, recovers from native album failures, passes offline audit with zero errors, and is not submitted until manual preview confirms that it is the game package.
