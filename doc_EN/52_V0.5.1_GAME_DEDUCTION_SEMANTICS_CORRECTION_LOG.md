# V0.5.1 Game Deduction Semantics Correction Log

Status: implemented and automatically verified

Date: 2026-10-01

## 1. Problem

The game editor described negative items as points deducted from the aggregate, but it reused `music-linear-100-v4`. That music algorithm multiplies ten-point negative inputs by ten before applying them to the 100-point result. Consequently, a template value of `-3` removed 30 aggregate points. Red Alert 2 had a positive weighted score of about 79.0 and was displayed as 49.0, contradicting the natural meaning of “deduct 3 points.”

## 2. Correction

- Added the game-specific `game-linear-100-v1` algorithm;
- Retained the shared positive-axis weights, unrated exclusion, and 100-point conversion;
- Game negative items now deduct direct percentage points, so `-3` removes 3 points;
- The editor, card preview, and PNG export use the same game calculation;
- Game card footers show `game-linear-100-v1`, while music remains on `music-linear-100-v4`;
- The editor now states the deduction unit explicitly.

## 3. Golden example

Red Alert 2 template:

- positive weighted score: approximately 78.9655;
- technology-age deduction: -3;
- final aggregate: 76.0 / 100.

## 4. Verification

- Unit coverage for the algorithm identifier, direct deductions, the Red Alert golden score, and zero clamping;
- Game template and storage regression coverage;
- Toy end-to-end coverage for editor score, card footer, and deduction guidance;
- TypeScript typecheck.

The music algorithm and music archives remain unchanged. Existing game template data such as `score: -3` requires no data migration; only the game-domain interpretation changes.
