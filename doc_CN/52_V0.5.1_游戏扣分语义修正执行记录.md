# V0.5.1 游戏扣分语义修正执行记录

状态：已实现并完成自动化验证

日期：2026-10-01

## 1. 问题

游戏编辑器把扣分项描述为综合分中的“扣分”，但此前直接复用了 `music-linear-100-v4`。该音乐算法把十分制负面项乘以 10 后再进入百分制总分，因此模板中的 `-3` 实际会扣除 30 分。红色警戒 2 模板的正向加权分约为 79.0，最终被计算为 49.0，与界面和模板中“扣 3 分”的自然含义不一致。

## 2. 修正

- 新增游戏算法 `game-linear-100-v1`；
- 正向评价轴继续复用既有权重、未评分排除和百分制换算；
- 游戏扣分项改为直接百分制扣分，`-3` 即从综合分扣 3 分；
- 编辑器、卡片预览和 PNG 导出统一使用游戏算法；
- 卡片页脚显示 `game-linear-100-v1`，音乐入口仍保持 `music-linear-100-v4`；
- 游戏编辑器明确提示扣分单位，避免再次误解。

## 3. 黄金样例

红色警戒 2 模板：

- 正向加权分：约 78.9655；
- 技术年代扣分：-3；
- 最终综合分：76.0 / 100。

## 4. 验证

- 游戏算法单元测试覆盖版本标识、直接扣分、红警黄金分数和最低 0 分；
- 游戏模板与存储回归测试通过；
- Toy 端到端测试验证编辑器、评分卡页脚与扣分说明使用同一语义；
- TypeScript 类型检查通过。

该调整不修改音乐算法和音乐存档；游戏模板的原始 `score: -3` 数据无需迁移，只改变游戏领域解释它的方式。
