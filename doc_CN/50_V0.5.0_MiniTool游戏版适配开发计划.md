# V0.5.0 MiniTool 游戏版适配开发计划

状态：适配规划；游戏 Toy 已有独立入口，游戏版 MiniTool 尚未交付

日期：2026-09-27

## 1. 背景与目标

当前仓库的 `minitool:build` 仍然构建音乐版小红书小工具。游戏版虽然已经具备独立页面、游戏模板、11 种比例评分卡和 Toy 构建，但还没有对应的 MiniTool 入口。直接复用音乐版打包脚本会得到音乐评分包，不能作为游戏版交付物。

本计划把游戏版适配为独立的离线 MiniTool，使用户可以在小红书容器内完成：打开游戏评分器、套用游戏模板、编辑评分、生成评分卡 PNG、保存到系统相册，并在能力不可用时得到可恢复的明确提示。

## 2. 适配边界

### 必须支持

- 游戏产品壳、游戏领域字段和四个带封面个人评价模板；
- 位于黑神话：悟空左侧的标准空白模板，套用后进入最基础的自定义状态；
- 简易模式、专业模式、自定义模式、评价轴、理由、扣分项和可选个人签名档；
- 11 种图片比例，预览与 PNG 使用同一个导出快照；
- 本地草稿和模板的 `localStorage` 恢复；
- MiniTool 原生相册保存 Bridge，包含能力探测、单次调用、成功、取消、拒绝和失败分类；
- Chrome 61 / Android 8.1 兼容的经典脚本构建产物；
- 离线运行，包内资源全部使用相对路径。

### 本阶段不支持

- `postNote` 发帖联动；该能力沿用分享机制计划，另立版本验收；
- 联网获取游戏资料、账号登录、排行榜或云端同步；
- 使用 `a[download]`、`window.open`、剪贴板和外部 CDN；
- 把 Toy 页面或音乐版 MiniTool 作为游戏版入口；
- 重新制作游戏评分算法。评分仍复用 `music-linear-100-v4` 的通用百分制契约。

## 3. 技术方案

### 3.1 独立入口

新增 `minitool-game/index.html` 和游戏版 MiniTool 构建配置，入口直接渲染游戏领域页面，不通过查询参数切换音乐与游戏。构建结果输出到 `dist-minitool-game/`，入口文件位于 ZIP 根目录。

游戏版 MiniTool 与现有音乐版 MiniTool 使用不同的构建产物、版本标识、存储键和包名，避免上传时误把音乐页面打进游戏包。

### 3.2 容器适配层

新增游戏版平台适配器，统一封装：

1. `isMiniToolRuntime()`：识别小红书容器，不把浏览器模拟器误报为原生能力可用；
2. `saveImageToAlbum()`：优先使用 `writeTempFile` 写入完整 `data:image/png;base64,...`，再调用 `saveImageToPhotosAlbum`；
3. `classifyNativeResult()`：统一返回 `success / cancelled / rejected / unavailable / failed`；
4. 浏览器回退：没有 Bridge 时保留预览与内存 PNG，提示用户手动保存，不调用受禁的文件下载行为；
5. 重复点击保护：一次保存请求完成前按钮进入忙碌状态，结果确认后恢复。

Bridge 仅调用 MiniTool 规范中列出的 `window.xhs.miniTool.*` API，参数和错误处理以适配文档为准。

### 3.3 导出一致性

编辑器、预览、PNG 导出和相册保存都读取同一份不可变快照。生成前记录 `draftRevision` 和比例；生成完成后如果内容已变动，保存操作提示用户重新生成，不复用旧图片。11 种比例、长标题、9 轴黑神话模板、空白模板和无封面状态都必须走同一导出计划。

## 4. 阶段计划

| 阶段 | 工作包 | 主要产物 | 完成门槛 |
| --- | --- | --- | --- |
| M0 | 入口与容器契约 | `minitool-game` 入口、Vite 配置、独立存储键、包名和版本标识 | 构建产物直接显示游戏页面，音乐文案为 0，资源均为相对路径 |
| M1 | 游戏编辑器移植 | 模板栏、空白模板、作品字段、评分轴、理由、扣分项、签名档 | 默认黑神话；空白模板位于其左侧且套用后清空；刷新可恢复 |
| M2 | 导出与原生相册 | 游戏版卡片快照、11 比例 PNG、Bridge 适配器和失败分类 | 预览与导出逐项一致；Bridge 不可用时可恢复，不白屏 |
| M3 | 真机兼容与性能 | Android 8.1/WebView 61 回归、窄屏安全区、封面压缩、触控优化 | 首屏、滚动、输入、模板套用和相册保存在目标设备完成 |
| M4 | 审计与交付 | ZIP、清单、SHA-256、静态审计、人工预览和发布说明 | 0 个 ERROR；无外链、无受禁 API、根目录含唯一 `index.html` |

## 5. 数据与存储约束

- 游戏 MiniTool 使用独立键：`xdrate.games.minitool.workspace.v1`、`xdrate.games.minitool.templates.v1`；
- 旧音乐 MiniTool 数据不得被读取、迁移或覆盖；
- 标准空白模板是普通可删除模板，但旧目录升级时若缺少该模板，首次迁移补入一次；
- 封面模板只保存包内资源引用或用户当前运行时的本地 Blob，不把二进制封面写入模板；
- 所有草稿、模板和导出状态都必须在存储不可用时降级到当前页面会话，并显示未保存提示。

## 6. 测试与验收矩阵

- 首次打开默认黑神话：悟空，显示 9 个评价轴；
- 点击左侧标准空白模板，再点击套用，作品字段和评价结构清空为自定义模式；
- 简易、专业、自定义模式可切换，模板套用不会修改种子模板；
- 红色警戒 2 的“官方剧情世界观”为 6 分、LV2；
- 11 种比例都能生成预览和 PNG，长标题、长理由、无封面不溢出；
- 相册保存成功、取消、拒绝、Bridge 缺失和异常均有明确状态并可再次操作；
- ZIP、路径、经典脚本、Chrome 61、受禁 API、体积和离线审计全部通过。

## 7. 交付物与发布顺序

1. `dist-minitool-game/` 构建目录；
2. `artifacts/minitool/xdrate-games-v0.5.0-<stage>.zip`；
3. ZIP 清单与 SHA-256；
4. 中英文适配说明、Bridge 结果记录和已知限制；
5. 人工预览截图和 Android 8.1 / 当前 Android 设备记录。

发布顺序固定为：本地测试 → 静态审计 → ZIP 验证 → 人工预览 → 真机相册保存 → 小红书 MiniTool 预览上传 → 明确确认后提交审核。

## 8. 退出条件

- 游戏版 MiniTool 可独立构建和打包，不再复用音乐版入口；
- 默认模板、标准空白模板、9 轴评分和红警预设在页面、预览、PNG 中一致；
- 原生相册保存闭环在 Bridge 可用和不可用两种环境均可恢复；
- 所有资源离线可加载，审计无 ERROR；
- 通过人工预览后，才进入 MiniTool 平台审核，不把当前音乐版包误更新到游戏入口。
